# Проверка страниц «Клиенты», «Компании», «Поставщики»

Дата: 9 сентября 2026 года. Изменения находятся в локальных CRM-Admin и CRM-AVIA-BACKEND; на PythonAnywhere не опубликованы.

## Исправления

- Реестры клиентов, компаний, сотрудников, поставщиков и связанные документы загружают все страницы API.
- Количество заказов, покупки, оборот и задолженность вычисляются backend по существующим заказам, услугам и обязательствам. Суммы разных валют показываются отдельно.
- Клиент редактируется вместе с профилем: сохраняются статус, контакты, город, гражданство, пол и комментарий. Исправлены сбой открытия карточки и обновление родительского состояния во время рендера.
- Документы клиента и документы при создании физлица/сотрудника сохраняются в backend. Некорректный документ откатывает создание физлица. Добавлены дополнительный телефон, отчество латиницей и комментарий документа. Скан можно связать с документом; карточка показывает сохранённые данные и ссылку на файл.
- Добавлено редактирование компании. Пустые контактные данные не создают фиктивного директора с ссылками `mailto:—`. У сотрудников больше нет безусловной отметки о соответствии политике.
- История заказов клиента/компании загружается отдельным запросом по идентификатору заказчика. Создание заказа из карточки передаёт выбранного клиента или компанию.
- Группы пассажиров, участники, подгруппы, переименование и архивирование работают через API. Список хранится зашифрованным; изменение проверяет версию. Без права просмотра документов номера скрыты.
- Импорт пассажиров читает фактический CSV/XLSX через backend. Убрана активная подстановка демонстрационного списка и угадывание пола/гражданства при экспорте.
- Пользовательские шаблоны и история объединения списков сохраняются в настройках backend.
- Excel/Word формируются на сервере как XLSX/DOCX. CSV поддерживает выбранный разделитель и кодировку. PDF открывает системную печать с возможностью сохранения в PDF. XML/JSON/текст содержат текущие строки таблицы.
- Финансовые, юридические и поисковые настройки поставщика сохраняются на уровне организации. Реквизиты API не попадают в обычный JSON настроек. Сохраняется совместимость с ранее сохранёнными личными настройками текущего пользователя.
- Наценки авиакомпаний сохраняются как правила backend. Конкретный маршрут имеет приоритет, учитываются авиакомпания и география; фиксированная наценка переводится в валюту цены по курсам организации. При отсутствии курса расчёт возвращает ошибку вместо неверной суммы.
- Версии файлов поставщика, просмотр и скачивание используют настоящие версии документов. Исправлена потеря фокуса при вводе реквизитов.
- Кнопки чата создают или открывают диалог, связанный с клиентом/сотрудником/поставщиком. Добавлена обработка ссылки на карточку поставщика.

## Проверки

Использовались изолированная локальная база и синтетические записи; рабочие данные PythonAnywhere не изменялись.

- Frontend: 318 тестов, production-сборка Next.js, проверка архитектуры и `git diff --check`.
- Backend: 462 теста проходят, включая регрессии создания документов, изоляции организаций, маскирования номеров, групп, импорта/экспорта, общих настроек и расчёта наценок.
- Ruff: изменённые Python-файлы проходят проверку.
- Миграции применены к локальной тестовой базе; `makemigrations --check --dry-run` не обнаруживает недостающих изменений.
- В браузере проверены создание клиента с паспортом, открытие карточки и редактирование города; создание компании и группы; создание локального поставщика; сохранение реквизитов и их повторное открытие после перезагрузки; переход в связанный чат поставщика.

Это не подтверждение каждого сочетания полей и всех внешних интеграций на рабочем сервере. Внешние реестры реквизитов не подключены; автоматическая передача списков поставщикам требует реального адаптера. Кнопка API создаёт ручную задачу и сообщает об этом. Чат CRM сам по себе не подключает Telegram/WhatsApp/email. Для наценок по географии адаптер должен передать географию либо коды стран сегментов; неизвестная география не угадывается.

## Установка

Перенести изменения **обоих** репозиториев. В backend обязательно включить новые миграции:

- `crm/migrations/0004_person_latin_middle_name_person_secondary_phone_and_more.py`
- `groups_app/migrations/0002_passengergroup_roster_and_more.py`

В консоли PythonAnywhere с активированным окружением проекта:

```bash
cd ~/CRM-AVIA-BACKEND
python manage.py migrate
python manage.py check
```

Затем нажать **Reload** приложения во вкладке **Web** PythonAnywhere. Если обновление выполняется через Git, сначала изменения нужно закоммитить и отправить в ваш репозиторий; локальные изменения сами на сервер не попадают.

Frontend пересобрать и перезапустить обычным способом (`npm run build`). Локальный адрес backend в `.env.local` сохранён: `https://crmbackend21.pythonanywhere.com`. Для проверки использовалось временное переопределение адреса процесса, а не изменение этого файла.
