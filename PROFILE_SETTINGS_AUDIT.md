# Проверка «Мой профиль» и «Настройки» — 08.09.2026

Изменения внесены в CRM-Admin и CRM-AVIA-BACKEND локально. На PythonAnywhere не опубликованы. Локальный frontend по умолчанию продолжает обращаться к https://crmbackend21.pythonanywhere.com. Для проверки использована отдельная SQLite-база /tmp/crm-profile-settings.sqlite3 и локальный Django; рабочие данные не изменялись.

## Исправлено

- Профиль: сохранение контактов MAX/WhatsApp, должности, подразделения и телефонов; защищённое чтение, загрузка и удаление аватара с проверкой содержимого файла; реальный последний вход и руководитель.
- Предпочтения: канонические значения, синхронизация языка с профилем, применение темы, форматов дат/времени, стартовой страницы, размера списков и валюты новых заказов. Добавлены переводы основных элементов профиля и настроек на English/Кыргызча. Полная локализация остальных разделов CRM не выполнена.
- Безопасность: смена пароля, завершение отдельных/остальных сессий, настройка и отключение 2FA, обработка ошибок. Настройки не сохраняются поверх незагруженных значений профиля.
- Доступы: точные соответствия видов услуг/действий API; явный запрет всех услуг больше не превращается в неограниченный доступ; сохранение дополнительных существующих прав. Управление защищено правами backend.
- Пользователи: атомарное создание с ролью, статусом и начальным паролем; блокировка/разблокировка; одноразовая ссылка приглашения и установка пароля.
- SLA доступен сотруднику для чтения, изменения ограничены правами администратора. История смен загружается полностью; длительность обновляется.
- Мотивация: индивидуальные ставки вместо изменения ставок всей организации, проверка процентов, сохранение заменённых правил в истории.
- Статистика: серверная выборка по сотруднику и периоду без ограничения первой страницей; раздельные суммы по валютам; CSV-экспорт.
- Валюты: добавление/удаление, положительные курсы, пересчёт при смене основной валюты, сохранение в организации и таблице ExchangeRate, восстановление справочника при входе.
- API: генерация действующих ключей с ограниченными разделами и доступом только для чтения; изменение названия и отзыв; секреты хранятся как хеши.
- Уведомления: сохранение персональных флагов и общих правил без удаления пользовательских правил; соответствие реальным событиям платежей; фильтры по услугам, действиям и просрочкам.
- Шаблоны документов: создание и редактирование с новыми версиями. Открываются справочники и формы настроек карточек услуг.

## Проверено

- Frontend: production-сборка `npm run build` успешна; 318 тестов; проверка архитектуры (65 прежних legacy-связей, 2 прежних цикла).
- Backend: полный набор — 450 тестов; после добавления истории мотивации профильный набор — 21 тест.
- В браузере: сохранение контактов; языки ru/en/ky; тёмная тема; сохранённые форматы и стартовая страница; пароль и повторный вход; включение 2FA, вход с кодом, отключение; отзыв сессии и выход с остальных устройств; статистика/кнопка CSV; SLA; индивидуальная мотивация; создание пользователя, блокировка/разблокировка; запрет всех услуг и повторное открытие; создание/редактирование шаблона; добавление/удаление валюты и пересчёт курсов; генерация/отзыв API-ключа; общие уведомления; поиск города; вкладки и сохранение карточек услуг.
- Загрузка/удаление аватара, одноразовое приглашение и ограничения API-ключей проверены серверными тестами. Не каждый элемент каждой формы отдельно пройден в браузере.

## Что не подключено

- Внешняя доставка SMS/Email/Telegram/WhatsApp/MAX/push: в backend есть очередь NotificationDelivery, но нет обработчика доставки. Одних переключателей недостаточно. В формах это указано; реальная отправка не заявляется.
- Автоматический расчёт начислений мотивации не подключён к жизненному циклу услуг. Ставки сохраняются; статистика читает уже зарегистрированные начисления. Для реализации расчёта и перерасчёта нужна отдельная интеграция с оформлением/обменом/возвратом.
- Справочник «Аэропорты и города» использует существующий поиск городов; полного редактируемого справочника аэропортов нет.
- Проверки выполнялись локально, работа новой версии на PythonAnywhere ещё не проверена.

## Установка на PythonAnywhere

1. Перенести изменения backend, включая новые файлы и миграции, в рабочий каталог сервера.
Дополнительно добавлена недостающая миграция orders/0002: состояние миграций приведено к уже существовавшему default RUB модели заказа. Существующие заказы она не пересчитывает.

2. В активированном виртуальном окружении backend выполнить `python manage.py migrate` с рабочими настройками Django.
3. Нажать Reload на вкладке Web PythonAnywhere.
4. Обновить frontend и выполнить `npm run build`, затем перезапустить его процесс.
5. Проверить вход, сохранение профиля и настройки против рабочего сервера. Не менять `.env.local`: адрес backend уже задан.

Рабочая база перед миграциями должна быть сохранена обычным способом резервного копирования проекта. Новые миграции не удаляют пользовательские данные.
