# Настройки организации

## Общие данные и взаимосвязи

- «Пользователи»: сотрудники текущей организации, стандартные роли, блокировка, приглашения, доступ к услугам и норматив отклика.
- «Организация и подразделения»: общий компонент с личным кабинетом, те же API и справочники. Подразделение содержит родителя, руководителя и роль по умолчанию; должность может переопределить роль. Изменение схемы действующих сотрудников создаёт заявки на пересогласование.
- «Роли и права»: все коды прав серверного каталога. Администратор защищён от изменения матрицы. После сохранения перепроверяется текущая сессия.
- «Параметры системы»: курсы организации, правила уведомлений, интеграционные ключи, шаблоны документов, справочники и карточки услуг. Пункты доступны по соответствующим правам; нормативы сотрудников вынесены из API-интеграций.
- «Аэропорты и города» используют тот же каталог и алгоритм поиска, что авиапоиск, включая группы «Все аэропорты».
- Типы и статусы шаблонов имеют русские подписи; API получает прежние коды. Изменение опубликованного шаблона создаёт следующую версию.
- Нет отдельного дублирующего списка ролей подразделений: выбор из `accounts.Role` той же организации.

## Проверка вручную

1. Администратор: Настройки → Организация и подразделения. Добавить подразделение, выбрать руководителя и стандартную роль; добавить должность. Сравнить с ЛК → Работа и структура.
2. Назначить схему тестовому сотруднику. Убедиться, что роль и руководитель в ЛК соответствуют схеме. Менять схему действующих сотрудников только осознанно: проверка согласования затрагивает реальные права.
3. В «Роли и права» проверить права тестовой роли и её фактический доступ после входа. Не менять рабочие роли ради проверки интерфейса.
4. В параметрах проверить валюты, шаблоны, норматив отклика и карточки: сохранённые значения должны сохраняться после повторного открытия.
5. В справочнике найти Москву, Нижний Новгород и код аэропорта; сравнить с авиапоиском.
6. При ошибке загрузки видимости клиентских полей или норматива кнопка сохранения недоступна: пустая форма не перезаписывает серверные настройки.

## Автоматические проверки

Регрессионные тесты UI покрывают права на вкладки, открытие общего компонента оргструктуры, назначение роли по стабильному коду при одинаковых названиях и запрет сохранения видимости после ошибки загрузки. Серверные тесты охватывают настройки, оргструктуру, роли, изоляцию организаций и управление API-ключами выделенной ролью интеграций без доступа к заказам. Производственные проверки выполняются без создания сотрудников, ключей или изменения рабочих ролей.
