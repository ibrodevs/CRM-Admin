# Проверка правок после обращения «Что за черновик восстановлен»

Дата: 14 ноября 2026. Диапазон истории: от `c5674e6` до `d190070`, плюс исправление восстановления отдельных форм создания заказа по результатам проверки.

## Результат

Проверены код, связи интерфейса с API, автоматические сценарии и доступность серверных методов на рабочем сервере. Найден и устранён один дефект восстановления черновиков создания заказа. Остальные перечисленные ниже изменения присутствуют в текущем коде; автоматические проверки завершились успешно.

Живую визуальную проверку кликами выполнить не удалось: подключение браузера вернуло `The browser access host is unavailable`. Успешные тесты и HTTP-ответы не заменяют проверку вёрстки в браузере на конкретном экране.

## Найденный и исправленный дефект

Раньше все новые заказы получали общий ключ списка `new-order`, а открытие ориентировалось на последнего выбранного клиента. При нескольких сохранённых формах это могло скрыть часть черновиков или открыть другую форму.

Теперь список использует полный ключ сохранённой формы; подпись включает выбранного клиента/компанию и групповой признак. При открытии точный ключ передаётся в форму заказа. Серверный заказ не создаётся и бронирование не запускается автоматически.

## Выполненные проверки

- Frontend: **603 теста — успешно**, включая два новых сценария восстановления. Production-сборка — успешно.
- Проверка архитектуры: успешно; новые циклические зависимости не добавлены.
- Backend: **981 тест — успешно**. Для тестового процесса использован `CORS_ALLOW_ALL_ORIGINS=True`, чтобы исключить влияние локального ограниченного списка origins. Рабочая настройка CORS не менялась. Есть предупреждения тестового набора о проверке пустого текста исключения, ошибок нет.
- Рабочий сервер: **16 read-only GET-проверок — HTTP 200**: профиль, статистика, предпочтения, состояние мессенджеров, отсутствия, пользователи, роли, оргструктура, валюты, карточки, API-доступы, правила/каналы уведомлений, шаблоны, SLA и доступ по услугам.
- В production не создавались бронирования, пользователи, ключи, отсутствия и назначения ролей ради проверки.

## Что нельзя считать завершённым

1. **Telegram, MAX, WhatsApp:** реальные каналы не подключены, поскольку реквизитов нет (подтверждено пользователем). Подготовленный механизм привязки не означает работающую доставку.
2. **Переработка экспресс-создания и сокращение шагов всех видов бронирования:** клиент предложил разобрать после текущих правок. Эта переработка не реализована и не входит в результаты выше.
3. **Визуальная приёмка:** автоматизированные проверки пройдены, но ручной прогон в подключённом браузере остаётся непроверенным из-за недоступности подключения.
4. **Цены допуслуг:** показываются только данные поставщика; отсутствующая цена обозначается как неизвестная, а не 0. До поиска точной цены может не быть.
